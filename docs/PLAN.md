# MBTI 오늘의 운세 — 서비스 계획서

> 작성일: 2026-10-12 · 상태: 초안

## 1. 한 줄 소개

내 MBTI를 고르면 **오늘의 운세**를 대인관계·일/학업·생활 리듬 세 가지로 알려주는 웹 서비스.

## 2. 왜 만드는가

- 사주는 생년월일·태어난 시까지 입력해야 해서 진입 장벽이 높다. MBTI는 대부분 자기 유형을 알고 있어 **클릭 한 번**이면 된다.
- 기존 MBTI 운세는 뉴스 기사 안에 16개 유형이 길게 나열돼 있어 내 유형을 찾으려면 스크롤해야 한다.
  → **내 유형만 바로** 보여주는 화면을 만든다.

## 3. 대상 사용자

- 자기 MBTI를 알고 있고, 가볍게 하루 운세를 확인하고 싶은 10~30대
- 친구와 "오늘 너 운세 뭐야?" 하며 공유하고 싶은 사람

## 4. 핵심 기능

| 우선순위 | 기능 | 설명 |
|---|---|---|
| 필수 | MBTI 선택 | 16개 유형 버튼 중 하나 선택 (선택값은 브라우저에 기억) |
| 필수 | 오늘의 운세 | 한 줄 운세 + 대인관계 + 일·학업 + 생활 리듬 카드 |
| 필수 | 날짜 넘기기 | 어제/내일 운세 보기 |
| 선택 | 친구 MBTI 비교 | 두 유형의 오늘 운세를 나란히 보기 |
| 선택 | 공유하기 | 결과 링크 복사 |

## 6. 데이터 (레퍼런스)

| 항목 | 내용 |
|---|---|
| 출처 | 비건뉴스 「오늘의 MBTI 운세」 (#MBTI 운세 태그) |
| 수집 방법 | Firecrawl API (`scripts/crawl.py`) |
| 수집 범위 | 2026-07-25 ~ 2026-10-10, 기사 30개 × 16유형 = 480건 |
| 구조 | 날짜 / 유형 / 한 줄 운세 / 대인관계 / 일·학업 / 생활 리듬 |
| 참고 사항 | 7~8월 기사는 항목 구분 없는 문단형(`text`), 9월 이후는 4항목 구조 |

**데이터 사용 원칙**
- 수집 데이터는 **기사 원문(저작물)**이므로 서비스 화면에 그대로 싣지 않는다. 문체·항목 구성·길이를 참고하는 **레퍼런스**로만 쓴다.
- 서비스에 쓰는 운세 문구는 직접 작성하거나, 레퍼런스의 구조를 참고해 새로 만든 문구 세트를 사용한다.
- 원문 데이터(`data/`)는 `.gitignore`로 GitHub에 올리지 않는다.

## 7. 기술 구성

| 구분 | 선택 | 이유 |
|---|---|---|
| 화면 | HTML + CSS + JavaScript | 서버 없이 동작, 입문자도 수정 쉬움 |
| 운세 데이터 | `app/fortunes.json` | 직접 만든 운세 문구 |
| 데이터 수집 | Python + Firecrawl | 레퍼런스 조사용 |
| 배포 | GitHub Pages (GitHub CLI `gh`) | 무료, 명령 몇 줄로 배포 |

## 10. 배포 방법 (예정)

```bash
gh auth login                                   # 처음 한 번 GitHub 로그인
git init && git add . && git commit -m "first"
gh repo create mbti-fortune --public --source=. --push
# app/ 폴더만 gh-pages 브랜치로 올리고 GitHub Pages 켜기
git subtree push --prefix app origin gh-pages
gh api -X POST repos/yeorm123/mbti-fortune/pages -f "source[branch]=gh-pages" -f "source[path]=/"
```
